# Candidate Assets Test Split 优化计划

## 背景

候选资产中心测试覆盖范围很深：复跑优先级、批量复跑、批量指派、归档、逾期升级、审批、生成草稿、复跑对比、晋升审批、baseline 应用、提醒确认、影响分析和回滚。原来这些动作集中在一个长测试里，单测耗时约 7.7 秒，失败时不容易判断是哪条业务链路断了。

## 目标

- 保留候选资产中心原有断言覆盖。
- 将长测试拆为按业务职责聚焦的测试：
  - 候选资产列表与复跑优先级。
  - 批量复跑、批量指派、归档和逾期升级。
  - 候选审批、生成草稿和复跑对比。
  - 晋升审批、baseline 应用、影响分析和回滚。
- 显式写清晋升审批依赖：候选必须先审批、生成草稿并完成复跑。
- 降低单个测试耗时，提升前端回归定位速度。

## 验证

- `cd frontend && npm test -- src/test/App.test.tsx -t "候选资产中心"`
- 收尾时执行前端全量测试、类型检查、构建和 E2E。
