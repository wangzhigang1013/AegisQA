# Report Page Test Split 优化计划

## 背景

报告中心测试已经覆盖报告摘要、诊断动作、导出、审批、Badcase 和 Trace 跳转，但这些动作集中在一个 20 秒上限的测试里。新增导出审批生命周期后，单个测试耗时约 14 秒，后续继续加功能容易出现偶发超时，而且失败时很难快速定位是哪一类交互坏了。

## 目标

- 保留原有断言覆盖，不降低测试质量。
- 把报告页大测试拆成更小的职责：
  - 基础报告渲染与质量决策。
  - 诊断动作、修复任务和分层门禁。
  - 任务报告 HTML/CSV/JSON 导出。
  - 导出审批生命周期。
  - Badcase 操作和 Trace Flow 跳转。
- 去掉单个报告测试的 20 秒特殊超时窗口。
- 让单个报告页测试耗时下降到 5 秒以内或接近 5 秒，方便后续定位回归。

## 验证

- `cd frontend && npm test -- src/test/App.test.tsx -t "报告中心"`
- 收尾时执行前端全量测试、类型检查、构建和 E2E。
